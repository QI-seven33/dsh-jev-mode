# DeepSeek 专项核对与 0.4.4 补充验证

日期：2026-10-17，北京时间。本文补充上一轮传输候选，记录继续推进时的真实核对；以 CHANGELOG 的最终交付状态为准。没有实施 0.5.0、切换主模型或 JEV 模型、改变授权阈值。

## 会改变优化判断的模型特性

1. [官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/) 当前要求：带 tools 的请求在后续调用完整传回历史 reasoning_content，包含此前未调用工具的回合；缺失可能返回 400。无 tools 的聊天则不同。Harness 实际走 Messages 协议，不能把 Chat Completions 的字段直接塞进宿主；本机原生适配器将保留的 reasoning blocks 与签名映射成 thinking blocks。不能通过删思考历史或重写旧消息来省 token。
2. 同一官方页面注明：思考模式忽略 temperature 等参数。`temperature=0` 不能证明决策确定或结果无噪声。生产主模型档位保持原样，辅助 model 路由的 off 只应作用于该次辅助请求；它也不构成小型生成模型与 TypeSafe 校准概率等价的证据。
3. [缓存说明](https://api-docs.deepseek.com/guides/kv_cache/) 要求完整复用已持久化的前缀单位，且缓存为 best effort。比起单独追求命中百分比，更应该分别测未缓存输入、命中输入、总输出和调用次数。少了一轮调用，后续重复输入也少，命中百分比下降仍可能伴随时间下降。
4. [隔离与限流说明](https://api-docs.deepseek.com/quick_start/rate_limit/) 把 user_id 用于缓存和调度隔离；不能每次请求随机换它来“改善”实验，也不能为共享缓存跨越用户边界。流式 keep-alive 注释代表连接仍在，不代表模型已开始有用输出，不能据此延长插件的绝对决策期限。
5. [当前模型与计费表](https://api-docs.deepseek.com/quick_start/pricing/) 将 deepseek-flash 映射到 DeepSeek-V4.1-Flash，区分缓存命中/未命中与输出价格。别名不是固定权重收据。本轮 SDK 未暴露服务端实际模型修订，报告将其标为 null，不把请求别名当作版本证明，也不拿未分离的 outputTokens 当成可见答案 token。

这些事实支持一个更有针对性的方向：减少无必要的规划与工具往返，同时保留宿主维护的思考连续性、工具结果、完整前缀和身份隔离。它们不支持动态删除历史、每轮改变工具目录、切主模型或宣称温度零保证稳定。

## 找到并修复的真实接入缺陷

原 createModelEngine 为保证请求不可变，会递归 Object.freeze 每个对象，包括 AbortSignal。在本机 Node 24.11.0 上，真实 DeepSeek 适配器使用 AbortSignal.any 组合信号，需要给信号添加内部依赖集合；冻结后抛出 `TypeError: object is not extensible`，请求无法正常开始。此前脚本化适配器不做这个操作，因此没有覆盖。

修复只冻结 plain object、数组及其普通数据，保留 AbortSignal 等运行时能力对象的内部可变性。请求、消息和文本块仍冻结；取消仍可传播。新增独立回归可在无宿主 CI 运行，并用真正的 DeepSeekAdapter 发出回环请求验证。

这影响显式/auto 后端中的辅助 model 路由；桌面预设固定 TypeSafe，不能说所有桌面 JEV 调用都被这个缺陷影响。没有改主模型的推理档位或服务端请求协议，也没有调整辅助请求的模型选择。

## 原生验证新增了什么

原生 DeepSeekAdapter + 合成 SSE，所有请求仅到 loopback，不用个人凭据：

- 先前有工具和无工具的两段合成思考及其签名都进入实际 Messages 请求；cacheReadTokens=90、inputTokens=10 分别映射，不混为一项。
- 辅助诊断请求实际发送 thinking=disabled；后续主请求仍为 thinking=enabled/high，证明设置只在本次请求生效。
- 插件真实 executeControlled 生成的 producer notice 进入请求后，原历史、思考签名、system 和 tools 保持，合成稳定匿名用户 id 不变。
- SSE keep-alive 可解析；只发 keep-alive 的服务仍在 40ms 决策预算到期后失败，不因心跳无限续命。
- 原生 V4 none/zstd 持久化测试新增合成 reasoning blocks；冷重开后两轮历史思考仍在，原前缀不变。

完整本机 npm test 通过，node:test 部分 29 项通过，原生测试未跳过。CI 的宿主缺失继续明确报告 skip，不把云端 skip 当作原生 DeepSeek 验证。

## 小范围真实 DeepSeek 诊断

使用既有官方 SDK 隔离载体，四次执行：项目清单和 README 两题，各标准/JEV 一次，交错运行。主模型均为 deepseek-account / deepseek-flash / high，每次最多三个主模型请求、2048 输出 token；提供方重试关闭，没有扩大失败样本补跑。主模型实际八个请求，TypeSafe 请求为零。

| 观察 | 标准模式（2 次） | 当前 JEV 模式（2 次） |
| --- | ---: | ---: |
| 客观题通过 | 2/2 | 2/2 |
| 主模型请求 | 6 | 2 |
| 两次耗时 | 2645 / 2305ms | 1384 / 1007ms |
| 未缓存输入 token | 7514 | 7549 |
| 命中输入 token | 30592 | 7040 |
| 输出 token | 205 | 56 |
| JEV 语义判断请求 | 0 | 0 |
| 前缀/工具目录违规 | 0 | 0 |

收益归因仍是明确读取的代码前置，不能归因于 JEV 判断或 0.4.4 的新传输逻辑；健康 TypeSafe 传输在这些样本里根本没有调用。只有每组两次，不能据此估计生产 P95、泛化成功率或宣称总体性能升级。两次标准请求链无可见 reasoning delta，不等于服务器完全没有思考或输出成本；一次混合请求观察到 65 个思考字符，这只是字符计数。

本轮改进基准观测，记录首个实际输出、首段可见文本、首个工具调用的等待和思考字符数，不记录思考正文。请求版本现在读取 package.json，修复此前报告硬编码 0.4.0 的问题。真实响应的 reasoning 原文没有加入新观测日志或公开材料；原生 Session 由宿主依既有机制管理。已有匿名用户 id 由宿主维护，本轮没有在真实链路抓取身份或认证请求头。

本机证据在 `E:\Codex\Workspace\jev-next-20261017-evidence`，包括 deepseek-full-tests.log、prefix-compare.json、deepseek-paired-smoke 的逐次报告及仅数值的 trace。源码只含合成测试和复现脚本，不包含账户配置或真实思考正文。

## 下一项实验的收窄建议

先保持 0.4.4 为可靠性发布。下一轮优先用现有数值观测区分：首次输出等待、可见思考、工具往返、输出生成、JEV 等待和磁盘等待。对普通任务不加判断，不通过降低主模型推理档位制造“JEV 提速”。

可以研究只在新一轮用户请求边界，根据确定性任务形态提供固定只读证据或一个已知验证结果，减少主模型再次规划；中途工具循环不得插入伪造人类授权、删 reasoning 或改已保留前缀。排队资源实验仍独立验证，暂不加到本次发布。先收集更多任务族和多次重复，再决定哪种新能力值得进入默认关闭的 0.5.0 实验。
